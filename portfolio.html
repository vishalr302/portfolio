01 / Data engineering + NLP / 2026

Grant Intelligence Platform

A transparent decision-support dashboard that ranks Northeast grant-funder prospects for EcoServants.

  • Python
  • Pandas + NLP
  • 100-point ranking
  • 5/5 tests
InputIRS Business Master File CSVs OutputRanked, explainable prospect list

Problem

Nonprofit development teams must screen large IRS Business Master File datasets to find grantmakers that may align with their mission. Manual review is slow, and a recommendation is not useful if a researcher cannot understand why a prospect ranked highly.

Approach

The platform cleans and deduplicates IRS data, identifies likely 501(c)(3) grantmakers, classifies mission alignment, compares organization text with EcoServants using TF-IDF and cosine similarity, and combines six transparent signals into a 100-point score.

  • Python
  • Pandas
  • scikit-learn
  • Streamlit
  • Plotly
  • pytest
View on GitHub ↗ Project brief

Key capabilities

Auditable prospect research

  • Reduces a large nonprofit registry to a reviewable shortlist so research can focus on stronger leads.
  • Assigns Environment/Conservation, Youth/Education, Community Improvement, Public Benefit, or Other mission categories.
  • Makes rankings inspectable through component scores, High/Medium/Low priority, matched terms, and a plain-language selection reason.
  • Handles multi-file upload, header and EIN normalization, invalid IDs, duplicate filings, missing text, financial and NTEE codes, and geographic scope.
  • Provides searchable tables, filters, Plotly charts, a ranked table, and CSV export through Streamlit.

Pipeline

From raw CSVs to ranked leads

  1. Upload CSV files or use the bundled sample
  2. Normalize, validate, and deduplicate records
  3. Keep the configured nine-state Northeast scope
  4. Screen likely 501(c)(3) grantmaker names
  5. Assign mission categories and TF-IDF similarity
  6. Calculate a 100-point score, priority, and reason
  7. Serve filters, charts, ranked table, and CSV export

Verification

5 tests passed

The automated suite covers cleaning, schema errors, mission categories, similarity and ranking, charts, and cached pipeline output. The shipped 14-row synthetic fixture resolves to two likely Northeast funders.

12 maintained project files · MIT licensed

Limitations

Decision support, not a funding guarantee

The ranking does not confirm that a foundation is accepting applications or will provide funding. IRS records may be incomplete or outdated, so every recommended prospect should be verified through the funder's website and recent Form 990 filings.

02 / Computer vision / 2025

NFL Pre-Snap Penalty Detector

An explainable computer vision prototype for first-pass review of broadcast football clips.

  • Python 3.10+
  • Computer vision
  • 4 rule flags
  • 9/9 tests
InputBroadcast football video OutputExplainable suspected-penalty flags

Problem

Reviewing broadcast footage for pre-snap penalties requires tracking player movement, team position, the line of scrimmage, the snap, and sometimes the play clock. Broadcast video introduces camera motion, occlusion, inconsistent colors, and uncertain field geometry.

Approach

The prototype applies YOLOv8 person detection frame by frame, links detections into player tracks, classifies teams with color heuristics, estimates the line of scrimmage and collective snap, optionally reads the play clock with OCR, and evaluates four explainable temporal rules.

  • Python
  • OpenCV
  • YOLOv8
  • NumPy
  • Tesseract OCR
  • pytest
GitHub repository ↗ Project brief

This repository URL is configured in the local project, but it is not currently publicly accessible.

Key capabilities

Explainable review flags

  • Flags false starts from sustained offensive movement before the estimated collective snap.
  • Flags offsides from a defender crossing the estimated line of scrimmage before the snap.
  • Flags delay of game from repeated OCR readings of zero before the snap and too many men from more than 11 active team tracks.
  • Keeps decisions inspectable through track IDs, event frames, confidence, snap frame, and estimated line of scrimmage.
  • Accepts manual offense, direction, line-of-scrimmage, and clock-region overrides when automatic assumptions are weak.

Pipeline

From video to review flags

  1. Accept CLI or script options and a video
  2. Read frames, dimensions, frame count, and FPS
  3. Detect people with YOLOv8
  4. Classify team colors and build proximity tracks
  5. Estimate line of scrimmage, snap, and optional clock OCR
  6. Evaluate four pre-snap rules
  7. Return structured results, reasons, labels, and annotations

Verification

9 tests passed

Tests cover line-of-scrimmage estimation, tracking continuity, all four rule evaluators, clock parsing, peak-motion snap selection, and video reads.

38 maintained or shipped files · MIT licensed

Limitations

Experimental flags, not officiating decisions

Camera motion, occlusion, legal shifts, inaccurate team-color classification, scoreboard delay, and an uncertain line of scrimmage can affect results. Delay-of-game evidence requires a tight play-clock region and a local Tesseract installation. The project should use only footage the user is authorized to analyze or distribute.

03 / Data collection + research tooling / 2026

Northeast Wildfire Smoke Scraper

An evidence-aware data collection pipeline for cross-border smoke events affecting the Northeast U.S.

  • Python standard library
  • 29 output fields
  • 15 source seeds
  • 3/3 tests
InputLocal or official web pages OutputCSV, JSON, and HTML reports

Problem

Wildfire-smoke evidence is spread across government, NOAA, NASA, EPA, emergency-management, university, and other official pages. Researchers need a consistent dataset without turning missing or uncertain evidence into unsupported claims.

Approach

The scraper fetches local or official pages, converts HTML to readable text, extracts assignment fields, filters for Northeast relevance, removes duplicates, and exports CSV, JSON, and HTML. Deterministic rules work without dependencies; optional AI assists difficult fields while provenance stays program-controlled.

  • Python
  • urllib
  • HTMLParser
  • dataclasses
  • CSV/JSON
  • unittest
GitHub profile ↗ Project brief

A project-specific GitHub repository has not been published yet.

Key capabilities

Evidence-aware collection

  • Produces a consistent 29-column research dataset covering incident identity, origin, smoke direction, affected communities, border status, AQI/PM2.5, advisories, effects, source URLs, and verification details.
  • Reduces repeated downloads with content hashing and cache support while respecting sources through rate limits and timeouts.
  • Uses explicit "Not Reported" and "Not Confirmed" safeguards so absent evidence is never silently turned into a claim.
  • Supports deterministic rules mode and optional OpenAI Responses API extraction for difficult fields.
  • Ships an offline NOAA-style fixture and demo outputs for repeatable review without internet access or API credentials.

Pipeline

From source pages to research data

  1. Load CLI options and source-seed JSON
  2. Fetch local or HTTP content with cache and rate limits
  3. Convert HTML into readable text
  4. Extract fields with rules and source hints
  5. Optionally enhance difficult evidence fields with AI
  6. Filter for Northeast relevance and deduplicate
  7. Export CSV, JSON, HTML, and an error summary

Verification

3 tests passed

The tests validate all 29 CSV fields and expected values, cross-border extraction, and the safeguard that unsupported border claims stay unconfirmed. All three demo export formats are included.

29 maintained files · Python 3.10+ package

Limitations

Evidence quality determines record quality

Long-range smoke reports often describe a regional complex rather than one named fire. The scraper does not invent incident acreage, dates, AQI, or damage figures: missing values remain "Not Reported," and uncertain border movement remains "Not Confirmed." AI mode requires API usage and human review, and source terms and request-rate limits must be respected.
